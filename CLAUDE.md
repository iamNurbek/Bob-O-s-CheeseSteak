# Bob-O's Cheesesteaks — Concept Demo Site

Portfolio/concept demo for Bob-O's Cheesesteaks (252 Main Street, Ridgefield Park, NJ).
The business is closed and the brand belongs to it, so a visible "concept demo" notice stays on the site.
Full spec: [bobos-website-plan.md](bobos-website-plan.md). Source menu: `Menu & Prices.png`.

## Layout of this repo
- Git root = this folder. The Next.js app lives in **`bobos-site/`** (run all npm commands there).
- `.github/workflows/ci.yml` runs from `bobos-site/` (format → lint → typecheck → unit/component/API → E2E → a11y).
- Husky hooks live in `bobos-site/.husky` (`core.hooksPath` is set by `npm run prepare`); pre-commit runs lint-staged.

## Environment
- Node 24 LTS via **nvm** (`~/.nvm`). A non-interactive shell may not load nvm: prefix commands with
  `export PATH="$HOME/.nvm/versions/node/v24.21.0/bin:$PATH"` or `source ~/.nvm/nvm.sh`.
- **Next.js 16.4** (App Router, Turbopack, `cacheComponents: true`, `partialPrefetching: true`), React 19.3,
  Tailwind v4, TypeScript strict, zod 4, next-themes, cva + clsx + tailwind-merge.
- Next 16 differs from older versions. Read `bobos-site/node_modules/next/dist/docs/` before using an API. Known gotchas:
  - `params`/`searchParams` are Promises; runtime data (`searchParams`, `cookies`, `headers`) must sit inside `<Suspense>`.
  - `error.tsx` receives `{ error, retry }` (not `reset`).
  - `PageProps<'/route'>` / `LayoutProps<'/'>` are global types generated by `next typegen`.

## Architecture rules
- `src/app/` = routing only (thin pages). `components/ui/` = generic primitives that **never** import feature code, `data/` or `providers/` (ESLint enforces this).
  `components/layout/` = Header/Footer/Container/Section/NavLink/ThemeToggle. `components/features/<feature>/` = restaurant-specific parts.
- `lib/` = pure, tested helpers (no React). `data/` = typed content (menu, hours, site). `constants/` = routes, limits. `types/` = shared types.
- Component folders: `Component.tsx` + `Component.test.tsx` + `index.ts`.
- Server Components by default; `'use client'` only for interactive parts.
- Text, prices and hours come from `data/`, never hard-coded in JSX. Routes from `constants/routes.ts`; tip options/limits from `constants/limits.ts`.

## Money
- Store and calculate **integer cents** only. All currency math lives in **`lib/money.ts`** (`toCents`, `formatPrice`, `calculateTotals`, line pricing). Nobody else does money math.
- Tip = 15/20/25% of **subtotal**, rounded once (15% of 1199 → 180), or a custom **dollar** amount clamped to [0, max].
- `POST /api/checkout` re-validates with zod and **recomputes totals on the server** from `data/menu.ts`, then returns `{ url: '/order/success?demo=true' }`. A "Demo only, no payment taken" note is always shown.

## Theming
- Tokens are defined once in `src/styles/tokens.css` (`:root` = light, `[data-theme='dark']` = dark) and mapped in `src/styles/globals.css` `@theme inline`.
- Use only semantic classes: `bg-bg`, `bg-surface`, `bg-surface-alt`, `text-text`, `text-muted`, `bg-primary`, `text-on-primary`, `bg-primary-strong`, `bg-accent`, `text-on-accent`, `text-accent-text`, `border-border`, `outline-focus`, `bg-scrim`, `shadow-card`, `rounded-card`, `rounded-control`, `max-w-content`, `font-display`.
- **Never** use raw hex, inline styles, default palette colors (`bg-red-600`), or `dark:` variants for brand colors.
- Never put white text on orange: use `text-on-accent` on `bg-accent`, and `text-accent-text` for orange text.
- `next-themes` with `attribute="data-theme"`, `defaultTheme="system"`. The ThemeToggle icon renders only after mount (`useMounted`).

## Code rules (condensed from plan §10)
- One component per file; PascalCase components, camelCase functions, `SCREAMING_SNAKE_CASE` constants, kebab-case non-component folders. Booleans start with `is/has/should`.
- Components under ~150 lines, functions under ~40. Early returns.
- No `any` (use `unknown` + narrowing). Explicit `Props` type. Union types over loose strings. zod schemas in `lib/validation.ts` are shared by client and API.
- Extract on the second use. Variants via props/cva, not copies.
- Comments explain *why*. Public helpers get a one-line doc comment. No commented-out code, no `console.log`, no unused imports.
- Imports: external → `@/` → relative, alphabetized, blank line between groups. Use `@/`, never `../`.
- Mobile first; spacing from Tailwind's 4px scale (1,2,3,4,6,8,12,16 = 4–64px).
- Every `lib/` function has unit tests; every bug fix adds a test. Handle loading/empty/error states.
- Conventional Commits (`feat:`, `fix:`, `test:`, `docs:`, `chore:`). Small, single-purpose commits. Never commit secrets (`.env.local`; `.env.example` lists names only).

## Accessibility (WCAG 2.1 AA, both themes)
- Active nav = color + 3px underline + `aria-current="page"`. Skip-to-content link. Visible `--focus` ring. 44px minimum touch targets.
- Modal/Drawer: `role="dialog"`, `aria-modal`, focus trap, Esc closes, focus returns to the trigger, body scroll locked.
- Tip selector and fulfillment toggle use radio-group semantics and work with the keyboard. Labeled fields with clear errors.
- Map iframe has a `title` plus a text address fallback. Respect `prefers-reduced-motion` and `prefers-color-scheme`.
